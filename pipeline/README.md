# pipeline/

Python scripts that turn NASA Earth Information Center (EIC) frames into the small data files the web app reads (`web/data/`). The format is defined in `docs/DATA-FORMAT.md`, section 2. The full validation report is `docs/VALIDATION.md`.

**Where the data comes from:** only NASA SVS visualizations 5176 and 5113. The challenge's Resources tab links the EIC gallery (https://svs.gsfc.nasa.gov/gallery/earth-information-center/), whose "Daily Visualizations" gallery ("the data visualizations that are updated daily for NASA's Earth Information Center") lists both. NASA GIBS is used only to check our decoding, never as a source of the app's values.

The browser cannot read pixels from svs.gsfc.nasa.gov (no CORS for other origins), so all decoding happens here and the site serves its own derived files.

## Setup

```bash
python -m pip install -r pipeline/requirements.txt
```

Downloaded frames go to `raw/` (git-ignored, never committed).

## Scripts

| Script | What it does | Output |
|---|---|---|
| `make_landmask.py` | Builds a 1-degree land/ocean mask from the SVS 5176 frame (land is drawn in neutral gray there). `--check` verifies the `surface` of every place in `places.py`. | `web/data/landmask.png`, `web/data/landmask.json` |
| `make_synthetic.py` | Development only: writes synthetic records in the contract format. It skips records that already hold real data, so it never touches the published records. | |
| `download.py` | Downloads the SVS 5176 colorbar and "nodates" frames (`sst`) and the SVS 5113 unlabeled frames (`fire`), for the 10th of every month. | `raw/5176/`, `raw/5113/` |
| `colorbar.py` | Reads the official colorbar EXR, finds its tick marks and inverts colors to values (nearest neighbour in CIELAB). | |
| `make_colorbar.py` | Ships the SVS 5176 color scale for the web app: the published colorbar with its labels, and the bare -4 to +4 °C gradient. `--check` decodes the strip with `colorbar.py` and compares it with the intended values. | `web/data/sst-anomaly/colorbar.jpg`, `colorbar-strip.png` |
| `build_sst.py` | Decodes every SST frame, aggregates to 1 degree and writes the `sst-anomaly` record. | `web/data/sst-anomaly/` |
| `validate_sst.py` | Compares our decoded cells with NASA GIBS and fills `meta.validation`. | `meta.json`, `validation.csv` |
| `build_fire.py` | Finds fire dots in the SVS 5113 frames and writes the `fire` record as hot-pixel density. `--stats` prints the distribution only. | `web/data/fire/` |
| `validate_fire.py` | Compares fire presence and ranking per cell with NASA GIBS VIIRS thermal anomalies. | `meta.json`, `validation.csv` |
| `common.py` | Grid, frame encoding (contract 2.4), polar disc projection (contract 2.5), JSON helpers. | |
| `make_hd.py` | Rewrites `display/` (1024 x 512), `display-hd/` (2048 x 1024), `display-uhd/` (4096 x 2048), `disc/` (1024 x 1024) and `disc-thumb/` (256 x 256) of both records from the raw frames, without re-decoding (`--display`, `--hd`, `--uhd`, `--disc`, `--thumb` pick tiers; `--thumb` alone downscales the existing discs and needs no raw frames). Adds `disc_thumb` to `meta.json` when missing, nothing else. `--check` verifies that every date has every file at the right size and 4:4:4 chroma, and compares the tiers with a fresh 1024 render. | `web/data/<record>/display*/`, `disc/`, `disc-thumb/` |
| `make_landmask_hd.py` | 4096 x 2048 land masks that match each record's frames pixel for pixel, so the globe can show the Earth on the side of the coast the record has no data for. `--record fire` builds the fire mask (default: SST). `--check` compares with `landmask.png` (SST) or with the base map and counts fire dots on the ocean side (fire), and writes an overlay to `raw/`. | `web/data/landmask-hd.png`, `web/data/landmask-fire-hd.png` |
| `make_sky.py` | Night sky backdrop from the SVS 4851 star map. `--check` locates known stars. | `web/css/img/sky-starmap-2048.jpg` (Milky Way glow; the stars themselves come from `make_stars.py` as `sky-stars.json`) |
| `make_textures.py` | Earth texture at 4096 x 2048 and the Moon map. `--check` compares with the 2048 Earth texture and locates lunar craters. | `web/css/img/earth-blue-marble-4096.jpg`, `moon-1024.jpg` |
| `places.py` | The 30 named places shown in the UI. `python pipeline/places.py` rewrites `places.json` only. | |

```bash
python pipeline/make_landmask.py --check
python pipeline/download.py sst
python pipeline/build_sst.py
python pipeline/validate_sst.py 12     # 12 cells per date
python pipeline/download.py fire
python pipeline/build_fire.py          # downloads the empty frame 900 (base map) if missing
python pipeline/validate_fire.py 16    # 16 cells per date
```

## Sea surface temperature anomaly (SVS 5176)

1. **Frames:** the "nodates" equirectangular EXR (4096 x 2048, linear RGB, no labels), one per month on the 10th, 2024-06-10 to 2026-11-10 (30 dates). The dated SVS frames of the same days are pixel-identical apart from the burned-in date.
2. **Colorbar:** `sst_mur_anomaly_auto_colorbar_01.exr`, same renderer and color space as the frames. The 9 white ticks (-4 to +4 °C) are detected automatically; colors are read from a clean band of rows under the ticks, giving 3,074 color steps. `make_colorbar.py` publishes the same colorbar for the UI, cropped to its content on its own black background (1600 x 364, with the NASA title, tick labels and "Degrees Celsius"; it carries no logo), plus a 1024 x 16 strip sampled from the middle of the bar between the -4 and +4 ticks, both through the same linear-to-sRGB conversion as the frames. Decoded back with `colorbar.py`, every strip pixel lands within 0.032 °C of its intended value (-4, 0 and +4 at the left end, center and right end), so the legend shown is the scale the decoder reads.
3. **Decoding:** each pixel goes to CIELAB and takes the value of the nearest colorbar color. Pixels more than 8 delta E away are no data. The split is clean: data pixels sit at a median delta E of 1.00 to 1.15 depending on the date, land and sea ice at 12 to 40, and under 1% of pixels fall in between.
4. **Aggregation:** median of valid pixels in each 1-degree cell; no data when fewer than half are valid (so coasts and the sea ice edge go silent instead of guessing).
5. **Saturation:** the scale ends at -4 and +4 °C. Cells at the ends are "at or beyond", never a measured value.
6. **Check:** 93 cells on 8 dates against NASA GIBS `GHRSST_L4_MUR_Sea_Surface_Temperature_Anomalies`, a separate NASA rendering of the same MUR data (0.1 °C classes, saturating at ±3 °C): mean absolute error 0.17 °C, bias +0.04 °C, 88% in the same class (cold, neutral, warm), correlation 0.97. This tests our decoding, not the satellite data. Our values run about 7% wider than GIBS (ours = 1.07 x GIBS), probably from different resampling and color quantization (not tested); we report it rather than tune it away. An independent re-decode with separate code agreed with our cells within 0.02 °C on average.
7. **Limits:** GIBS saturates at ±3 °C, so the +3 to +4 °C range (where the 2026 El Niño sits) is checked only as "at least +3 °C". About 1% of ocean cells hold two water masses (for example the Agulhas or the Brazil-Malvinas confluence); there the cell median is less stable.

## Active fires (SVS 5113)

1. **Frames:** the "SoaS" equirectangular EXR without labels (4096 x 2048, about 10 km per pixel). Each frame draws every VIIRS fire detection (Suomi NPP and NOAA-21) of a 5-day moving window as a dot colored by fire radiative power, over a fixed base map of black land and dark blue ocean.
2. **Dates:** the frames are numbered 001 to 900, not dated, and cover only the **last two years** (despite the "2024-Present" title). Dates were read from the date stamp of the labeled EIC version of the same generation (2026-11-14), on 11 frames: `date(n) = 2024-11-13 + floor((n - 1) * 730 / 899)` days. The SVS regenerates the frames daily, so `download.py fire` refuses frames from another generation.
3. **Window:** SVS says "moving five-day window" without saying how it aligns with the date. NASA GIBS daily detections match the 5 days ending on the frame date best. This is inferred, not documented.
4. **Fire pixels:** the newest frames (2026-11-11 to 2026-11-13) are still empty, so frame 900 is the exact base map. A pixel is fire when it is more than 20 delta E away from the same pixel of that empty frame, whatever the dot color (red, yellow, white, or the gray of a white dot blended with black land). Two empty frames differ by at most 5.4 delta E. An earlier version matched dot colors to the colorbar and missed white and gray dots; it was replaced.
5. **Density:** fire pixels / land pixels in each 1-degree cell; no data when less than half of the cell is land.
6. **Relative, not burned area:** dots are drawn about 10 km wide for 375 m detections and overlap over 5 days, so the value is the share of map pixels covered by fire dots in the SVS rendering, not the share of land that burned. Rankings are robust; absolute values depend on the rendering. The unit is "% of land pixels with fire dots".
7. **Scale:** fixed for all dates, 0 to 50%, saturating above. Half of the cells with fire are under 4%, 90% under 35%; 6.6% of fire cells saturate, mostly African savannas at the peak of their season.
8. **Never power:** overlapping dots over 5 days do not give a power per cell, so fire radiative power (MW) is never reported. Dot colors are used only to see where fire is.
9. **Excluded:** 2026-11-10. The newest frames are still being filled in near real time: that date has about half the fire pixels of 2025-11-10, file sizes drop from 2026-11-07, and 2026-11-11 to 2026-11-13 are empty.
10. **Check:** 80 cells on 5 dates against NASA GIBS `VIIRS_SNPP_Thermal_Anomalies_375m_All` and `VIIRS_NOAA21_Thermal_Anomalies_375m_All` (union of the 5 days ending on the date). Half the cells have fire in our data; the other half have none but sit within 3 cells of a fire, between 60°S and 60°N, outside Greenland (a hard test, no free agreement from ice sheets). Fire presence agrees in 97.5% of cells (1 missed, 1 extra). Among cells with fire, the ranking of amounts matches with Spearman rho 0.94. Our values are about 4 times the GIBS coverage, because GIBS draws the same detections at a different size: only presence and ranking are comparable.
11. **Noise:** each date is one 5-day window, so a single cell jumps between dates (Uberlândia: 22.0% on 2025-09-10, 3.0% on 2026-09-10). Compare contrasts the wet season with the dry season, never one year against another.

Dates: the 10th of every month, 2024-12-10 to 2026-10-10 (23 dates). The 2024 fire season is no longer in the frames; the dry seasons available are 2025 and 2026.

## High-resolution images and globe textures

All sources are public domain NASA images; downloads go to `raw/` (git-ignored). None of these scripts touches `frames/*.png`, `validation.csv` or the values in `meta.json`.

- **Chroma:** every display tier (`display`, `display-hd`, `display-uhd`) is saved with full 4:4:4 chroma (`common.DISPLAY_SUBSAMPLING = 0`). At 4:2:0 the red and orange fire dots over Southeast Asia washed toward yellow (chroma error on colored pixels 8.7 vs 5.6 levels at 4096) and the SST fronts smeared (Gulf Stream crop: 99th percentile error 36 vs 21). `display` and `display-hd` were 4:2:0 until 15 Nov; they were re-encoded at 4:4:4 from the same raw frames and conversion, same quality (a fresh 4:2:0 encode of the same pixels is byte-identical to the old files, so only the chroma changed). Cost: SST `display` 3.45 to 4.99 MB, `display-hd` 10.32 to 14.76 MB; fire `display` 0.87 to 1.13 MB, `display-hd` 2.53 to 3.27 MB (6.97 MB more in total).
- **`display-hd/{date}.jpg`** (`make_hd.py`, also written by the build scripts): the same frame as `display/{date}.jpg`, through the same linear-to-sRGB conversion and Lanczos resize, at 2048 x 1024 (JPEG quality 80, progressive, about 140 to 500 KB). Downscaled back to 1024 x 512 it differs from the display image by less than that image's own JPEG noise. `meta.json` names it as `display_hd` (contract 2.3).
- **`display-uhd/{date}.jpg`** (same scripts): the same frame at the native 4096 x 2048, quality 82. Named `display_uhd` in `meta.json`.
- **`landmask-hd.png`** (`make_landmask_hd.py`): 4096 x 2048, white = land, black = ocean. A pixel is land when, on all 30 SST dates, the decoder classes it as no data AND it is not the flat light gray SVS draws for sea ice (sRGB level 150 or more; land gray is about 80 to 125). The decoder rule alone would keep the central Arctic pack, which never melts in these frames, so the gray rule keeps it out. Ice shelves, the ice sheets and lakes the frame draws in land gray (for example the Great Lakes) count as land. The edge is a Gaussian blur of 0.6 px. Land share 34.2%; aggregated to 1 degree it agrees with `landmask.png` in 98.3% of cells. Named `land_mask` in the SST `meta.json`.
- **`landmask-fire-hd.png`** (`make_landmask_hd.py --record fire`): the same encoding for the fire record, because the SST mask does not fit the fire frames. Against the fire base map, 33% of the coastal band (2 px either side of the coast) disagrees: SVS 5113 draws big lakes and inland seas as water (the Caspian, the Great Lakes, Lakes Victoria, Ladoga and Baikal, Great Bear and Great Slave), the SST frames draw them as land gray, and Arctic and Antarctic coasts sit 1 to 3 px apart between the two renderings. Land is the black land of the empty frame 900, the exact base map under every fire frame, with the rule `build_fire.py` uses for the density (nearer to land black than to ocean blue in CIELAB); the empty frame has no fire dots and no JPEG noise, so no consensus over dates is needed. Lakes count as water, as the frame draws them. Land then grows by 2 px (Euclidean disk, `FIRE_GROW_PX`) before the edge is softened: the globe shows the lit Blue Marble on the water side, and the Blue Marble coastline often sits just offshore of the frame's (1 px offshore of the base map's coast 20% of the Blue Marble is land, 2 px 11%, 3 px 8%, against about 4% far from coasts), which drew a thin light sliver of Blue Marble land or shallow shelf along coasts. Growing land only shows more of the frame's own pixels (the flat ocean fill and the soft black coast), never hides data, and the globe keeps every frame pixel that is not the flat ocean fill anyway. Simulated at 4096 x 2048 on 2025-09-10 (60°S to 60°N), the bright sliver (Blue Marble pixels shown within 3 px of the coast and 20 levels brighter than the water 4 to 8 px out) drops from 0.29 to 0.08 per coast pixel (radius 1.5 would leave 0.13); 1.35% of all pixels turn from water to land. The density in `build_fire.py` does not use this file. The SST mask is not grown: its gray land fill would cover valid coastal SST pixels, and there the frame shows no land gray beyond 1 px of the mask coast (0.5% of that ring, none further out). Land share 35.3%, 204 KB. Before the 2 px growth, on each date 1.4 to 2.3% of the fire pixels (860 to 2,008) fell on the ocean side of the base map's coast, 9,051 distinct pixels over the 23 dates; outside the grown mask 2,608 remain. They are dot rims that cross the coast (median 1 px from it) and offshore gas flares (Gulf of Mexico, Persian Gulf, Niger Delta, Santos Basin, off Angola and Vietnam), which a picture that shows only the land side of the frame would hide. Named `land_mask` in the fire `meta.json` (`../landmask-fire-hd.png`, outside `fire/` because `build_fire.py` rewrites that folder).
- **`disc/{date}.jpg`**: 1024 x 1024, sampled from the full 4096 x 2048 sRGB frame, at 2x and box-filtered down (no aliasing from the radial squeeze). Same projection and orientation as before (contract 2.5).
- **`disc-thumb/{date}.jpg`** (`common.save_disc`, called by the build scripts and `make_hd.py --disc`; `make_hd.py --thumb` makes them from the existing `disc/` files): the disc downscaled to 256 x 256 with Lanczos, never the other way round, JPEG quality 70 with 4:4:4 chroma, progressive. About 20 KB per SST date (19 to 21 KB) and 6 KB per fire date (the fire disc is mostly black land); 0.75 MB for all 53 dates. For the small picture of the record (56 to 84 CSS px), which loads one per date during Play. Same projection, orientation and black outside as the disc. Named `disc_thumb` in `meta.json`.
- **Night sky** (`make_sky.py`): NASA SVS 4851 "Deep Star Maps 2020", the star map in celestial (equatorial J2000) coordinates, `starmap_2020_8k.exr` (not the `_gal` galactic variant). Averaged 2 x 2 in linear light, then tone-mapped: black point, gain, a toe so the faint haze stays black, and a shoulder that keeps the brightest star under sRGB 255. JPEG quality steps down only as far as needed to fit 450 KB. Only the 2048 x 1024 map ships: the globe draws stars as crisp points from `sky-stars.json` (`make_stars.py`, the brightest 9000 point sources of the same NASA map) and uses this image for the Milky Way glow. **Orientation:** plate carree; column `x` is right ascension `RA = 12h - 24h * (x + 0.5) / width`, so the center column is RA 0h and RA increases to the left; row 0 is declination +90 (north up). `--check` finds Sirius, Canopus and Vega within 1 pixel of where this formula puts them.
- **Earth 4096** (`make_textures.py`): Blue Marble Next Generation with topography and bathymetry, October 2004 (`world.topo.bathy.200410.3x5400x2700.jpg`), the month the existing `earth-blue-marble-2048.jpg` was made from (mean absolute difference 2.3 levels at 2048 x 1024; the other months differ by 5.7 to 10 levels, mostly in snow cover).
- **Moon** (`make_textures.py`): NASA SVS 4720 "CGI Moon Kit", LROC color map (`lroc_color_2k.jpg`, 2019 version), 1024 x 512, longitude 0 at the center, east to the right, north up.
